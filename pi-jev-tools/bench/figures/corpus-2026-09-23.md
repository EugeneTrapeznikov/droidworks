## Notes

- The earlier 84% coverage reproduces as 84.7% under allowlist + ≥ 2,000 chars on the whole result. The handler's extra gates (skip errors, take the largest text part, need ≥ 3 blocks) lower it to 81.5%; that is the figure's "eligible".
- Cross-check: `~/.pi/agent/pi-jev/replay/cases/triage.jsonl` has 30,866 cases (read 18,191, bash 8,030, fetch_url 3,671, mcp* 742), blocks p50 7 / p95 34; this run finds 30,872 (6 more `read` results from sessions added since the cases were built).
- State-cap overflow uses `buildState` exactly: budget = cap − task context (last user prompt + last sentence of the last assistant text, capped at min(2,000, cap/4)) − tool name; blocks are judged while the leading run fits.
- Session count is 1,080 here vs 1,073 in the README: sessions written since that run.
- Percentiles are nearest-rank; sizes are the sum of text parts per result (same as `scripts/mine-sessions-cost.py`).

## Commands

```bash
cd pi-jev-tools
python3 scripts/mine-corpus-triage.py > corpus.json   # every number above; ~4 s, read-only

# cross-check against the replay cases file
python3 -c "
import json,collections
c=collections.Counter();b=[]
for l in open('$HOME/.pi/agent/pi-jev/replay/cases/triage.jsonl'):
  d=json.loads(l); c[d['tool'] if not d['tool'].startswith('mcp') else 'mcp*']+=1; b.append(len(d['blocks']))
b.sort(); n=len(b); print(n, c.most_common(8), b[n//2], b[int(.95*n)])"
```
