## Reproducing the local (kev) column

```sh
# 1. kev itself (clone anywhere), MLX on Apple Silicon
KEV_TEMPERATURE=1.3 uv run --extra serve python -m kev.serve --run jaredpalmer/kev-0.8b --port 8009
# 2. the sidecar that translates kev's answers into the extension's contract
uv run --python .venv/bin/python local-judge/server.py --engine kev --model http://127.0.0.1:8009
# 3. the replay, on the same stratified sample as the other judges
export PI_JEV_LOCAL_URL=http://127.0.0.1:47411 PI_JEV_TIMEOUT_MS=3000 PI_JEV_BENCH_CONCURRENCY=1
bun run bench/replay/cli.ts judge --judge local --sample stratified --limit 2000
bun run bench/replay/cli.ts score --judge local && bun run bench/replay/cli.ts report
```

`PI_JEV_BENCH_CONCURRENCY=1` matters: `kev.serve` answers one request at a time, so the default
8-way fan-out measures queueing, not the judge (p50 2,654 ms at 8 vs 341 ms at 1, measured on
the prompt-level cases of the deferred prefix idea).

## Request shape

Each case sends the extension's own request: `buildState` (task context in the extension's
`taskContext` format, tool name, and the leading run of full-text blocks that fits the judge's
state cap) and `buildQuestions` (one noul per judged block plus the error question). Blocks past
the cap are unjudged and kept, as in the extension.

Block splitting, the judge state, tool matching, the question set and the `decide()` policy are imported from
`extension/src/triage/core.ts` — the bench keeps no copies, so replay cannot drift from what ships.

## Reading the numbers

- **Sampling.** Triage is scored on the same 2,000-case stratified sample for every judge. Every
  judge sees the identical case ids, so the columns are paired and differences are the ranker, not
  the sample.
- `local` is kev-0.8b (or JevK5), `mock` the deterministic noise floor.
- The error gate is the judge's own answer to the error question, as in the extension: P ≥ 0.5
  (or no answer) keeps the whole result. There is no regex fallback.
- **`local` loses triage on question wording, not on model quality.** kev answers "yes" to
  almost every block (AUC 0.525, only 2.8% of blocks under P=0.1), so the shipped policy prunes
  64 of 2,000 cases. `local-judge/RESULTS.md` §4 measured exactly this and
  named the cause: the bare phrasing "Is this block needed for the current task?" scores 0.30 on
  kev-0.8b, and adding "Answer no if it is from an unrelated file or an unrelated part of the
  code" takes the same model on the same items to 0.75. The rerun above replaces this column.
- **`local` triage covers 1,974 of the 2,000 cases.** kev enforces 8,192 tokens per *question*
  ("branch too long: N tokens with an M-token state (row limit 8192)"), and 26 replay cases have a
  single 25-line block over that — pathological one-line-per-megabyte tool output. The current
  splitter hard-splits any line over 1,500 chars, so no block can reach that limit. 322 triage cases also needed
  more than the 3,000 ms first pass and were re-judged at `--timeout-ms 60000`.
- Two views. The **threshold sweep** measures the ranker alone. The **shipped policy**
  row runs the extension's real `decide()` — head and tail pinned, error gate,
  20% minimum prune ratio — and is the number that predicts production.
- Weak labels are recall-oriented: a block counts as needed if a later edit reuses one of its
  distinctive lines, a later read opens a path it names, or the final answer quotes an identifier
  from it. Blocks that only informed the model's reasoning are labelled not-needed, so regret is a
  lower bound on real cost.
